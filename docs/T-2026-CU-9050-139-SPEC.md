# T-2026-CU-9050-139 — Bypass reader rewiring + reversible write-path cutover (C-gate phase 5 prep)

## Intent

C-gate phase 5 (dropping the ~9.3k per-coin `{SYM}_{tf}[_indicators]` tables) is blocked
as long as **currently running** code still reads these tables via raw SQL. This task moves
every active direct per-coin reader to `core.candles` (hyper-capable since T-128, live since
2026-07-16) and builds a **reversible write-path flag** with which the writers can write
hyper-primary on a trial basis (legacy off), so Michi can measure the write-/storage
performance gain **before** the tables get dropped.

Two-part task: **(A)** read rewiring of all active bypass sites, **(B)** reversible
write-cutover flag.

## Context / grounding

- **Read API already exists** (T-034/T-128): `read_candles`, `read_candles_with_indicators`,
  `latest_open_time` — with `source==hyper` live. Rewiring = raw SQL → this API, byte parity.
- **Write API exists** (T-114/T-119): `upsert_candles`/`upsert_indicators` write
  **legacy primary** + mirror to hyper when `KYTHERA_CANDLES_DUAL_WRITE=1`. There is **no**
  hyper-primary mode — that's exactly what gets built in part B.
- **Pattern:** blocks 1–6 (DESC→ASC via `.iloc[::-1]`, `Decimal`→`float` cast, `include_forming`
  cutoff clock-based, no consumer reindex).
- Decision **D-2026-CLD-109**; hard rules CLAUDE.md #5 (closed candles only), #7 (shared
  feature builders = trainer==serving), #8 (caller commits the transaction).

## Out of scope (deliberate)

- `legacy_trainers/*` (frozen provenance, `zzz.py` = scratch — hard rule: don't touch old trainer
  provenance) and `db_schema_analysis.py` (catalog diagnostic, will simply report 0 after the drop).
  **These will break on the table drop — deliberate, documented.**
- `tools/audit/step7_monitor_replay.py` — TZ-forensic **throwaway** script (manual, CI-excluded). Its
  5m gap census (`generate_series` over `{coin}_5m`) AND the coin enumeration from the per-coin table
  names depend structurally on per-coin existence; making it fully drop-safe would need the
  `SELECT DISTINCT symbol` scan over the 40M-row hypertable, which T-128 deliberately avoids (>20 s). Disproportionate for a
  throwaway → breaks on the drop like `legacy_trainers`, accepted (Michi scope 2026-07-16).
- **Delete/retention helpers** (`delete_candles_before`, `delete_indicators_from`) deliberately do **not**
  honor `_write_primary()` — AC7 applies only to the `upsert_*` writes. Under `WRITE_PRIMARY=hyper` they keep
  deleting from the (then frozen) legacy per-coin tables; hypertable retention is phase-5 policy
  (compression). Benign for the gated write-only perf trial. **Operational note:** a
  `tools/recompute_indicators.py` run during the trial edited legacy (invalidate→recompute), while
  reads come from hyper — no read-visible effect, but legacy drifts further. Delete-primary
  awareness would be a follow-up task if the trial runs long.
- The **actual** `WRITE_PRIMARY=hyper` flip + fleet restart (Michi-gated, perf trial).
- The **table drop** itself (phase 5, after a positive trial + 7d + pg_dump — Michi-gated).
- `11_ai_mis_bot`, `core/research_features` — already on `core.candles` (blocks 4/5).

## Why build (reuse verdict phase 0b)

**Extend**, not build: read sites use the existing `core.candles` read API (reuse);
part B **extends** `core.candles.upsert_*` with the primary selector. No new library.

## Risk note

Part B is the risky part: a bug in the write-primary selector can cause the
ingestion to write **nothing** or to the **wrong** table = live data loss. Hence:
DB-gated write parity with rollback, default stays `legacy`, the flip is Michi-gated.
