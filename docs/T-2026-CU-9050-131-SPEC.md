# SPEC — T-2026-CU-9050-131: Analytics Export (DuckDB/Parquet) + Success-Rate Endpoint

## Intent
First implementation task of Z1 stage 1 (curation mcp-a868a761829e). Builds the dashboard's
analytics data substrate: `tools/analytics_export.py` incrementally pulls, via watermark, only
*closed* rows from four live PG sources into a columnar substrate (date-partitioned Parquet +
one DuckDB file), plus a first API endpoint (success-rate time series, rolling 7/30/90d, bot
multiselect) that reads **exclusively against DuckDB** — never against live PG.

## Why Build (Phase 0b reuse check → Build)
- **z-search-first need:** "incremental PG→DuckDB/Parquet sync via watermark, DB-free testable".
- **Verdict:** Build. The DuckDB/Parquet sync is, per curation (mcp-a868a761829e point 4), the
  *fixed, sole* analytics path — there's no existing Cu tool for this. Reuse at the library
  level: DuckDB (native Parquet reader/writer, **no pyarrow needed**) instead of building our own
  columnar storage. No reinventing — the code is pure orchestration around DuckDB.
